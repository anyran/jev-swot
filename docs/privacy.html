做题 Jev 隐私政策

最后更新：2026 年 9 月 23 日

做题 Jev 只在用户通过快捷键、扩展按钮或 Alt + 双击主动触发时处理网页题目，不出售数据、不投放广告，也不自动勾选或提交网页答案。主快捷键为 Ctrl/Command + Shift + Y；若与浏览器或其他扩展冲突，可在 chrome://extensions/shortcuts 设置备用的 Windows/Linux: Alt + Shift + Y；macOS: Command + Shift + U。结果默认以低干扰的透明文字提示显示，详情通过图标按钮按需打开。

处理的数据

  • Alt + 双击会显示整页逐题面板；用户点击“开始整页分析”后，扩展逐屏扫描主网页及浏览器允许读取的 HTTP/HTTPS 嵌入框架，包括视口外和滚动后才加载的题目，并分别处理每道题。题目文本只在确认后发送，跨域框架文本也遵循此确认；扫描会滚动主页面、框架和内部滚动区，结束或取消后恢复位置。受浏览器限制或缺少站点访问权限的框架会显示未扫描提示。
  • HTTP/HTTPS 网页访问是可选权限。用户显式启用后，Alt + 双击整页扫描可在已打开网页中持续使用；未启用时，扩展按钮和框选快捷键仍通过用户主动触发的临时权限工作。
  • DOM 不完整时，扩展在本地逐屏拼接主网页题目截图。本地 PP-OCRv5 在设备上处理截图且不上传截图；只有视觉模型可用且用户逐题允许时，主网页题目截图才会发送至用户配置的 API。为避免子框架坐标错位，框架视觉题不会自动截图，会提示用户单独打开识别。用户选择“仅本地 OCR”时不会上传图片。Chrome 的 captureVisibleTab 需要 <all_urls> 或当前页 activeTab 权限；扩展不申请 <all_urls>，而由用户点击扩展图标或触发已注册的浏览器快捷键授予临时 activeTab 权限。若浏览器拒绝截图，结果面板会提示用户授权后逐题重试。
  • 如果模型不支持视觉，本地 OCR 文字和文本框位置会先按视觉行分组。配置 JEV 时，普通文本模型返回题干、选项和排除行证据，扩展据此重建边界；题号、答案、解析、得分、对错标记和页面杂讯不会进入 JEV，也不会发送原始截图。未配置 JEV 时，OCR 原文会整体发送给普通模型判断，详情才进行题干/候选项分离。
  • 用户配置的 JEV 决策 API（默认 TypeSafe，也可配置 OpenRouter 等兼容服务）接收用户确认后的题干、上下文和选项，以返回选项概率。首次使用自定义 API 域名时，设置页会在保存或测试连接时单独申请该域名的网络权限；拒绝权限后不会向该域名发送请求。
  • 结构化题目点击“普通模型答题”时，普通模型收到已确认的题干、上下文和选项；视觉直答和未配置 JEV 的 OCR 直答返回可能答案、教学解释、知识点和不确定性。详情通过紧凑图标按需打开，不在页面持续显示大块弹窗。
  • 只有用户点击“答案解析”后，结构化题目及 JEV 概率才会额外发送至用户配置的普通模型。

存储与保留

  • JEV 与普通模型的地址、模型名、能力设置和 API Key 保存在本机 chrome.storage.local，浏览器重启后仍会恢复，不会同步到云端。
  • OCR 阈值、WebGPU 开关、视觉上传确认和禁用站点列表也保存在 chrome.storage.local。
  • 设置页的“清除本次会话”只清除当前会话缓存；“清除 API Key”会删除会话和本机保存的密钥。
  • 扩展不持久保存网页正文、截图、OCR 内容、题目、答案或模型响应。

第三方服务

扩展会按用户操作调用用户配置的 JEV 决策 API（例如 TypeSafe 或 OpenRouter），以及用户自行配置的 OpenAI 兼容 API。相应服务的数据处理受其各自政策约束。

控制与联系

用户可以禁用指定站点、清除 API Key、释放本地 OCR 内存，或卸载扩展。问题可通过 GitHub Issues 提交。
